# Colony machinery and structure props

Original flat-colour frontier artwork, extending the existing furniture palette:
olive panels, worn gunmetal, warm timber, pale enamel and small amber/cyan indicators.
The 20 glTF/bin pairs are generated by `tools/make_world_props.py`, using the shared
mesh and glTF helpers. No textures, transparent surfaces or additional point lights.

```sh
python3 -B tools/make_world_props.py
python3 -B tools/preview_world_props.py --out target/world-props-review
cargo run --release --example look -- --world-props
```

The set covers twelve production stations, four power devices, stairs, ladders,
graves and fences. Each asset has five materials and 112–628 triangles across all
its meshes (a state scene draws only the pieces it needs). Keep new props below
2,000 triangles and five materials.

Models use cell units, +Y up and the fallback's local facing. Worktop heights,
footprints and back reach retain the existing work/placement references. Stair
treads remain at 0.25, 0.5, 0.75 and 1.0; ladders retain their original rail/rung
positions. Definition transforms, rotation and wall placement still apply outside
the glTF instance. Construction previews use per-instance blue ghost materials.

`BuildModel.scenes` is a validated string with one of three layouts:

- `Static` (default): scene zero.
- `Filled`: scene zero is the open grave (marker/pit), scene one the filled grave
  (marker/mound). The existing burial state selects it.
- `Connected`: scene 0–15 corresponds to the local four-direction connection mask,
  in `Dir` order: +X, -X, +Z, -Z. All scenes share one post mesh and four rail meshes.
  World connections are rotated into local space before selecting the scene.

All keep their state-matched shape fallback while the model loads. Missing/failed
loads leave those shapes visible; replacing or removing the prop removes its entire
entity hierarchy. Structural walls, openings, floors, roofs, wallpaper and joins
continue to use the existing grid renderer.

CPU geometry tests cover finite/unit normals, material/triangle budgets, contact
surfaces, state-scene assembly and exact regeneration. Rust tests cover placement,
scene selection, cache invalidation, blueprints and loading fallback lifecycles.
The CPU gallery includes every state from the actual definition transforms, front
and rear at a common cell scale. It is not an in-game screenshot.

GPU acceptance is pending: the implementation session could not find a GPU, even
outside the sandbox. Review daylight/night, normal/close zoom, all rotations, ghosts,
hidden layers/roofs, crafters at stations and dense-colony frame time before closing 10d.

## CPU cache benchmark (2026-10-20)

Release build on the development machine; median of three runs, with 6,664 props
on the same unoccupied 100x70 map and 1,000 warmed cached updates per run:

| Representation | Initial spawn | Cached sync | Entities before scene loading |
|---|---:|---:|---:|
| Original shapes | 5.72 ms | 0.06 µs | 37,332 |
| Model roots plus loading fallbacks | 25.57 ms | 0.06 µs | 77,103 |

The benchmark uses empty scene handles, so this measures CPU hierarchy setup and
prop-cache synchronization, not glTF decoding, loaded mesh propagation, GPU frame
time or the entire app frame. Initial model setup costs more; cached sync does not
rebuild the scene. Run it explicitly (it is excluded from ordinary test runs):

```sh
cargo test --release --bin my-world benchmark_dense_world_prop_sync -- --ignored --nocapture
```
